# Review: 2026-10-10

## What the project is for

An MCP server for a padel player. Ask an assistant "where can I play near me tonight, 18:00 to 21:00?", compare prices across clubs, keep favourites, and get alerted when a slot opens. The second goal is a showcase: rich MCP-UI widgets for Goose and ChatGPT Apps, including a demo checkout. The repo had 22 commits, the last on 2026-01-30.

## What I found live

1. **Playtomic is not integrated, and its old API host no longer exists.** `services/playtomic.ts` has been 100% mock data since commit b44bca2 (Jan 2026): 38 fictional venues with generated slots. The original client, last seen in 1565caa, called `https://api.playtomic.io/v1/tenants` and `/availability`. That host is NXDOMAIN today. `playtomic.io` redirects to `playtomic.com`, and `app.playtomic.io/api/v1/...` returns 404. The README and both IMPLEMENTATION docs claimed "real Playtomic API integration" with OAuth and rate limiting. None of that code exists.
2. **The hosted server is down.** `padel-mcp.onrender.com` returns 503 "This service has been suspended by its owner". `padel-finder-mcp.onrender.com` (the name in render.yaml) returns 404. The GitHub repo has no homepage set.
3. **The other upstreams work.** Nominatim geocoding and Open-Meteo weather both returned 200.
4. **Dependencies have drifted.** The MCP SDK was 1.25.1; the latest is 1.32.1. The other majors behind are zod 4, vite 8, preact 11, @mcp-ui/server 6 and TypeScript 7. `npm audit` reported 9 vulnerabilities (1 critical, 5 high) in the SDK's transitive deps (express, qs and others).
5. **The build was not broken.** `npm ci`, `npm run build` and `npm run typecheck` all passed before any changes. One local quirk: this machine has npm `script-shell` set to PowerShell 5.1, which can't run the `&&` in the scripts. I set `npm_config_script_shell` to Git Bash to work around it.

## What changed

| Change | Why |
|---|---|
| Registered `check_alerts` | Alerts could be created but nothing could ever evaluate them, so no notification was ever sent. |
| Registered `quick_search` | It existed but was unreachable. It covers "tonight", "tomorrow" and "weekend" without date math. |
| Removed the `test_hello_world` and `test_slot_cards` tools, plus `src/_widget-renderer_backup/` | Debug noise in the LLM's tool list, and dead code. |
| `console.log` → `console.error` in geocoding and check_alerts | Writing to stdout corrupts the stdio JSON-RPC stream. The geocoding fallback path did this. |
| SSE server creates one `McpServer` per connection (`createPadelServer()`) | A shared instance only tracks the latest transport. When any client disconnected, every other session broke. |
| Server `instructions` | Tells the model the data is simulated, that `book_court` never books, and which tool fits which question. |
| Tool boundary validation | Unknown `venue_id`, a reversed time window or a past date are now rejected by `set_availability_alert`. Previously those created alerts that could never fire. `check_availability` rejects unknown venues instead of saying "no slots". Location-not-found responses now set `isError: true`. |
| `find_available_games.date` is optional and defaults to today | The common "today" case needs no date. |
| Local dates instead of UTC | `toISOString().split('T')[0]` gave the wrong "today" between midnight and 01:00 BST. Mock slots also parsed dates as UTC midnight. |
| Descriptions | `book_court` is labelled DEMO ONLY. The alert tools explain that nothing polls automatically. |
| Dependencies | Ran `npm audit fix`; production deps now have 0 vulnerabilities. The SDK is at 1.32.1. Removed the unused `@vitejs/plugin-react` and `esbuild` dev deps. 2 dev-only advisories remain in vite 5 / esbuild. |
| `npm test` | Smoke test (`scripts/smoke.mjs`): builds, starts the stdio server, lists tools, runs a search, checks the validation errors, and confirms an alert set then checked actually fires. It uses a temporary HOME. |
| Docs | README rewritten to match the code. IMPLEMENTATION_COMPLETE/STATUS removed (they were inaccurate and duplicated the README). `.env.example` trimmed to the only variable that is read (`PORT`). Unused GEOCODING_* constants removed. ## Remaining suggestions (ranked)

1. **Real data source (L).** The core product promise is unmet. Options: the official Playtomic partner API (needs credentials), or reverse-engineering the current playtomic.com app API (fragile, and check the ToS). Keep the exported functions in `services/playtomic.ts` as the swap point. Every tool goes through them.
2. **Scheduled alert delivery (S/M).** Add a `--check-alerts` CLI mode, or a `setInterval` in the HTTP server gated by an env var, so alerts fire without a model calling `check_alerts`. Pair it with a Telegram/ntfy webhook example.
3. **Shrink the tool surface (S).** There are 19 tools with overlapping jobs: `find_cheapest_time` vs `compare_prices`, `search_by_duration` vs filters, `get_weekly_availability` vs `quick_search`. Merging these into `find_available_games` options would help model tool selection.
4. **Delete or wire the 7 unregistered tool files (S).** friends, group-games, invite, booking-history, calendar-feed, track-booking and search-with-filters total about 2,000 lines that never run. The CheckoutWizard widget calls `track_booking`, which isn't registered.
5. **Hosting (S).** Either un-suspend Render (and point render.yaml's service name at the real URL) or drop render.yaml. If hosted, `~/.padel-finder` is ephemeral and shared by all users, so favourites and alerts need per-user storage.
6. **Move to Streamable HTTP (M).** SSE transport is deprecated in the MCP spec. The SDK's `StreamableHTTPServerTransport` is a near drop-in replacement.
7. **Default-location tool (S).** `quick_search` reads `default_location`, but no tool sets it.
8. **Dependency majors (M).** zod 4, vite 8 (clears the dev advisories), preact 11, @mcp-ui/server 6. Do each one separately and run `npm test` after each.
9. **Response size (S).** Every search returns markdown, a full JSON block and an HTML resource. Trimming to a single representation would cut tokens substantially.
